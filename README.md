# Bambu Smart Tuner

拓竹 3D 打印机的独立桌面调参工具。读 Bambu Studio 保存的 `.3mf` 工程，
按「机型 + 耗材 + 喷嘴 + 优化模式 + 模型几何」自动算出一整套切片工艺参数，
另存成新 3mf，回到 Bambu Studio 直接切片。

不是插件，是独立程序，可打包成单文件 Windows EXE。

```
① 加载 3mf → ② 识别机型/耗材/喷嘴/真机上限/板面 → ③ 选模式与打印板/室温
   → ④ 规则引擎算全套参数（工艺页 + 热床风扇 + 机器页）
   → ⑤ 结论卡 + 对比表 → ⑥ 另存新 3mf（v2，不覆盖旧版）
```

**核心约束：不去动机器几何，也不改耗材的物性参数（压力提前/回抽/流量/AMS 槽位）。**
温度与风扇只按「耗材 × 板子 × 室温」推导后写入耗材槽并显式声明，
机器页只在你在界面换了机型时才重写。

---

**一句话说明**：你把 3mf 丢进来，选好机型/耗材/喷嘴，点一次优化，
程序算好一整套参数并另存一份新 3mf —— 拿回 Bambu Studio 直接切片就行。
界面最上面那张「结论卡」直接告诉你**这次调完的结果**（哪里变快、哪里更好看、
哪里更不容易翘边），下面那堆参数表只是给想深挖的人看的。

**写入范围（v1.2 起）**：工艺页（速度/加速度/层高/线宽/支撑/接缝）
＋ 热床温度与风扇（耗材页）＋ 机器页（机型/板面尺寸/机器上限）。
其余耗材页参数（压力提前、回抽、流量、AMS 槽位）仍然只读不改，
只读取它们的真实值来约束工艺参数。

## 0.1 它是「按模型算」还是「套预设」？—— 分三层说清

这一条被问得最多，所以把它摊开。每次优化产生的每个参数，来源只有三种，
程序会把每个键最后被谁改写记下来，结论卡里直接给出比例：

**① 预设基准表（起点）** —— 机型预设 × 耗材预设 × 模式档。
它只提供「这个组合的常规值」，例如 `outer_wall_speed: 200`。
这一层确实是预设，任何调参工具都躲不掉：总得有个起点。

**② 按你的模型实测（真正属于「针对这个模型」的部分）** ——
加载 3mf 时对每个对象做**逐层截面采样**（Bambu 的三角面 → 每层的
x/y 包围与面积），得到这些量，再拿量去定参数：

| 实测出来的量 | 由它决定什么 |
| --- | --- |
| 每层截面面积、包围盒 → 悬垂面积比 | 要不要开支撑、支撑密度与接触线距、裙边宽度 |
| 细高比（高度 ÷ 最小边） | 首层附着加强、擦料塔/裙边、接缝对齐方式 |
| 圆度（截面面积 ÷ 包围盒面积 是否接近 π/4） | 圆柱件斜接缝、`apply_scarf_seam_on_circles` |
| 体积、最大截面、壁厚估计 | 填充图案与密度、墙圈数、层高上限 |
| 顶面占比、颈部收缩比 | 顶面熨烫/图案、层高与速度的取舍 |
| 板子类型 × 耗材 × 室温 | 热床温度、首层温度、风扇上下限 |
| 悬垂角度分布 | 外壁速度、冷却策略、支撑形态 |

同一个 3mf，改一个对象的尺寸，上面这些量就变，写出来的参数也就变 ——
这就是「针对模型」的实际含义。可以自己验：界面「推导复核」页签里
每条都是「实测值 ÷ 公式 = 结论」，手算能对上。

**③ 安全钳制** —— 规则算出来的值再过一层边界（层高上下限、
体积流量上限、机器加速度上限、Studio 的成对约束），保证不会写出切不动的值。

**诚实的边界**：它不是 AI，没有训练数据，也不会自我改进。
它是一套**几何测量 + 规则表**。规则表覆盖的场景有限（目前 18 个机型、
5 类耗材、6 档模式），遇到规则表没见过的组合只能给保守值。
真要往前一步，缺的不是更复杂的算法，而是**实测回流**：
同一个模型切成 A/B 两版实际打印、量尺寸、拍断面，把「这组参数在什么件上
成了/废了」记下来，再拿这批数据去校准规则表里的系数。
这件事没有捷径，但也不需要玄学 —— 需要的是能对齐的样本量。

## 0. 版本记录

### v1.2.2（2026-11-26）— 按模型算的覆盖面加大：悬垂位置 / 桥接跨度 / 站得稳不稳

这一版不再只看「体块比例」，而是把**悬垂落在哪、有多宽**量出来，让不同件真的拿到不同参数：

| 新量 | 怎么量 | 决定什么 |
|---|---|---|
| 最长悬垂边 `max_bridge_span` | 所有朝下（悬垂）三角面的最长投影边 | ≥20 mm 且悬垂占比 ≥3% → 桥接速度压到 ≤30 mm/s |
| 悬垂高度分布 `overhang_top_ratio` | 悬垂面积里落在上部 40% 高度的比例 | ≥60% → 支撑接触面顶层 +1（上面没东西托，得多压一层） |
| 站得稳不稳 | 细高比 ≥3 且脚底 <2500 mm² | 裙边加宽到 ≥6 mm、outer_only、首层 ≤40 mm/s |

同时补上了一个一直没接的地方：**自动档的支撑开关终于按几何判断了**。
以前 `support_plan.decide` 写好了却没人调用，所以「支撑根据模型调」只调了密度和形态，
开关一直不动 —— 有悬垂的件照样一张支撑都不长。现在：

* 几何算出来需要支撑 → 自动写 `enable_support=1`，并提醒你去 Studio 核一眼落点（用「阻止支撑」刷子刷掉多余的）；
* 几何算出来不需要 → 不擅自关掉你工程里本来就开着的支撑；
* 你在下拉里选「强制关闭」→ 几何判断不许把它再打开。

支撑相关键（`enable_support` / `support_base_pattern_spacing` / `support_top_z_distance` /
`support_interface_top_layers` …）也加进「标准键」白名单：老工程里整段缺失时照样补写进去，
不然又会变成「调了半天没生效」。

实测（`samples/shape_tower_overhang.3mf` 对 `shape_plate_flat.3mf`）：
塔拿到 `bridge_speed=30`、`enable_support=1`、`support_interface_top_layers=3`、`brim_type=outer_only`、`initial_layer_speed=40`；
平板一个都没拿（`bridge_speed` 不在写入里、支撑不开、首层仍是 42）。
新增 `tests/test_model_smart.py` 13 条守着这个「不同件必须不同参数」。

### v1.2.1（2026-11-26）— 修 v1.2 的界面与「不同步」

这一版只修问题，不加新功能。

* **界面串行**：v1.2 把「打印板/室温/风扇偏置/支撑好拆」塞进了已有行，
  结果「原始值」标签压在打印板下拉上、逐件明细盖住方案下拉，
  ③ 优化模式整块被挤出可视区。现在行位重排，三块明细（逐件明细 /
  推导复核 / 真机同步）收进下方页签，**结论卡固定在页签区上方**，
  开窗就能看到「这样调完会怎样」，不用滚。
* **换了喷嘴但机型没换时机器页不同步**：旧逻辑「同一台机器就什么都不做」，
  于是 0.6 喷嘴的工程保存出来机器页仍是 0.4，Studio 继续按 0.4 切。
  现在单独比对 `nozzle_diameter` / `printer_variant` / `printer_settings_id`
  三项，不一致就只改这三行。
* **打印板默认写死 Supertack**：用 Textured PEI 的工程会被写成 Supertack 的板温，
  还连带改 `curr_bed_type`。现在下拉第一项是**（跟随工程）**，加载工程时按
  工程里的 `curr_bed_type` 自动选，手动改才覆盖。
* **首层板温方向反了**：原来首层比其余层**低** 5°C（`initial_layer_delta: -5`），
  首层最需要抓板的时候反而最凉 —— 天冷翘边有一半是这个原因。
  现在是首层**高** 5°C（PETG + Supertack = 首层 75 / 其余 70）。
* **「打一个盒子降速严重」** → 三条根因，全部修掉：
  ① 薄壁误判——用 `thickness_index`（S/V^(2/3)）判薄壁，而那个量对**实心平板**
  同样很大（160×120×8 算出来 15 > 9.5），普通盒子被贴上「薄壁/镂空」，
  连带吃到一串降速规则。改用「平均壁厚 2V/S + 填充率」。
  ② 重复扣分——形状层把首层速度 ×0.85，几何层又按同一个理由再乘一次，
  50 mm/s 被叠成 36。现在形状层改过的键会留痕，几何层/推导层不再叠乘（50 → 42）。
  ③ 静默降速——降了不说为什么。结论卡新增一行「速度：外壁 200→137，
  内壁 300→174（被体积流量上限 18 mm³/s 压着，想更快就换高流量热端或降层高）」。
* **室温一填就自动落到板温和风速上，并且看得见**：结论卡新增一行
  「热床 设为 78°C · 风扇 min 10% / max 40%（室温 12°C：热床 70 → 78°C、
  风扇再降 10 个百分点）」——填完室温不用再点任何东西。
* **新增「写入核对」页签**：保存后把「表格里显示的值」和「新文件里实际存的值」
  逐键列出来（参数 / 表格里的值 / 文件里的值 / ✅已写入 or ⚠不一致），
  一眼看出哪些真进了文件；Studio 打开若仍显示旧值，那一段还教你看
  「已声明预设差异」那行日志。
* **结论卡新增「模型判定」一行**：把这次识别出的形状（扁平板 / 小体积 /
  高瘦易晃 / 圆柱）写出来，说明参数为什么是这一套。
* **「方案关了」→ 关掉方案能撤销了**：原来切回「（不套方案）」只是不再套用，
  界面还停在方案里（选了「外观优先」再关掉，模式仍是精细）。现在第一次套用时
  会快照你原来那一屏设置，关掉就还原；在方案之间来回切，撤销点始终是
  「你自己的设置」，不会被中间那套方案污染。日志会写
  「已关闭方案，参数回到套用之前的设置」。
* **打印板改成中文名**：下拉里显示「超粘板 Supertack / 纹理 PEI 板 / 光滑 PEI 板 /
  高温板 / 工程板 / 低温板」，写进工程的仍是 Studio 只认的英文板型串
  （`curr_bed_type` 一个字都不改），推导复核里的行标题也跟着中文化。
* **室温改成点一下直接输入**：去掉了上下小箭头（`NoButtons`），空格位显示
  「不指定（点这里输入）」。风扇那一项同理，并把「风扇偏置」改名为
  **「风扇强弱」**（偏置是行话，用户不知道是什么）。
* **新控件加了一行白话解释**：打印板 × 室温管热床温度与首层温度、风扇强弱是
  整体加减、支撑好拆只改拆的难易。
* **结论卡新增「改动依据」**：每个写入的键都记录最后改它的那一层，结论卡直接给
  「按模型实测 N 项 / 预设基准 M 项 / 保持原值 K 项」，用来回答
  「这软件是按我的模型算的，还是套预设」。

### v1.2.0（2026-11-26）— 修「参数不生效」+ 热床风速/支撑好拆/接缝/方案

**三个 bug（用户实测反馈）**
* **参数有时生效有时不生效** → 根因：热床温度、风扇转速是**耗材页**的键，
  旧版只声明了工艺槽（`different_settings_to_system[0]`），耗材槽是空的，
  Bambu Studio 便按耗材预设把它们盖回默认。现在**三槽分别声明**
  （工艺 / 耗材 / 机器），声明过的键 Studio 才会采用文件里的值。
* **选了机型后生成的 3mf 不对应** → 根因：从不重写机器页。现在按你选的机型
  重写 `printer_model` / `printer_settings_id` / `printable_area` /
  `printable_height` / `machine_max_*`，并在机器槽声明；换机型时额外提醒做校准。
* **手动选机型后参数变回默认** → 同上（机器页 + 槽位声明双管齐下）。

**新增**
* **热床与风速（耗材 × 板子 × 室温）**：新增「打印板」下拉与「室温」输入。
  热床温度按耗材×板子的官方基线取，再按室温补偿（≤5°C +15°C、≤10°C +12°C、
  ≤15°C +8°C、≤20°C +4°C）；冷天（<18°C）风扇自动再降一档。
  风扇另有 ±30% 手动偏置。天冷翘边的根就在这两项。
* **支撑好拆三档**：标准 / 好拆（推荐）/ 极好拆。放大顶面与底面 Z 间隙、
  减少接触面层数、放宽接触线距 —— 拆支撑不崩面。
* **圆柱件斜接缝**：按几何识别圆柱/圆管（截面面积比接近 π/4），自动把接缝
  对齐成一条竖线并整套打开斜接缝（`apply_scarf_seam_on_circles` 等），
  侧面那条竖线基本看不见；代价是整体慢约 2~5%（会写进结论卡）。
* **参数方案（预设）**：内置三套「快速出件 / 外观优先 / 冷天不翘边」，
  也可把当前设置存成自己的方案（存 `%APPDATA%\BambuSmartTuner\presets.json`）。
  方案存的是**决策输入**而非固化数值，规则库更新后自动用上新规则。
* **结论卡**：界面顶部直接给「这样调完会怎样」的几条结论，不用自己读参数表。
* **保存即核对**：写出 3mf 后重新打开逐键比对，不一致会明确报出来。
* **第二版保留第一版**：输出名固定为 `<原名>_optimized_v2_<时间戳>.3mf`，
  永不覆盖原工程与上一次的输出，可以并排比较。

## 1. 快速开始

### 1.1 跑源码

```bash
pip install -r requirements.txt        # 只装 PySide6 就能跑
python app.py
python app.py 某个工程.3mf              # 启动即加载
```

### 1.2 打包成 EXE

```bat
build_exe.bat
```

或：

```powershell
.\build_exe.ps1                          # 全新打包
.\build_exe.ps1 -SkipDeps -Mirror tuna   # 跳过装依赖 + 清华镜像
```

产物：

```
dist\BambuSmartTuner.exe        约 44 MB，单文件，双击即用
dist\rules\BambuRules.json      规则库（放这里改，不用重新打包）
```

`dist` 目录可整个拷走，目标机器不用装 Python。

### 1.3 命令行

```bash
python cli.py analyze  工程.3mf                     # 只分析识别结果与模型形状
python cli.py optimize 工程.3mf -m quality           # 优化并另存
python cli.py optimize 工程.3mf --custom-filament "彩格petg" --md
python cli.py batch    samples -m balanced --md      # 批量处理整个目录
python cli.py sync-filaments --export my_filaments.json
python cli.py rules                                  # 规则库概览 + 自检
```

| — | `GENERIC` | 识别失败时的通用保守兜底 | 300 | 8000 | 8 | 15 | 0.08~0.28 | 220×220×250 |

H2 家族的关键差异（都是从官方 `Bambu Lab <机型> 0.4 nozzle` 预设沿 `inherits`
链读出来的真值，不是估的）：

* 运动平台速度上限 1000 mm/s（X1/P1/A1 是 500，P2S 是 600，H3C/P3C 是 1400），空走加速度 9000；
* Z 轴速度 30 mm/s、Z 加速度 500；
* 热端更猛：`nozzle_volume` H2D/H2D Pro 130 mm³、H2S 145 mm³、H2C 130 mm³（X1C 107）；
* 热床更大：H2D/H2D Pro 350×320、H2S 340×320、H2C 330×320，Z 高 325 / 340 / 325；
* 带辅助风扇与腔温控制（`auxiliary_fan` / `support_chamber_temp_control` = 1）。

### 1.5.1 2.09 新增机型的三个坑（都是真机数据揭示的）

1. **A2L 不是「大号 H2」而是「大号 A1」**：热床 330×320×325 比 A1 大一倍，
   但加速度上限只有 **12000**、熔池只有 **92 mm³**、无辅助风扇、开放机架。
   把它当 H2 调（1000/20000）会直接丢步。
2. **X2D 熔池只有 92 mm³**：速度上限 1000、加速度 20000 看着很猛，
   但热端和 A1 同级。0.4 喷嘴 + 0.2 层高 + 0.42 线宽时，92 mm³/s 只能挤出约
   **1095 mm/s** 的理论上限，实际还要打折 —— 不换高流量热端就先撞流量墙，
   这也是本程序把「热端流量类型」做成一个独立维度的原因（见 §7.9）。
3. **H3C 的 Z Jerk 只有 1**（H2 系是 3、X1 系是 3）：Z 方向换层顿挫大，
   `z_hop` 抬高要保守，`z_hop_types` 优先 `Normal` 而不是 `Spiral`。

| 机型 | PLA | PETG | ABS | ASA | TPU |
| --- | --- | --- | --- | --- | --- |
| A2L | 21 | 18 | 16 | 18 | 3.6 |
| H2C | 25 | 21 | 20 | 20 | 3.6 |
| H3C | 25 | 18 | 20 | 20 | 3.6 |
| P3C | 25 | 18 | 20 | 20 | 3.6 |
| X2D | 22 | 21 | 16 | 18 | 3.6 |

> A2L 的 PLA 官方没出 `@BBL A2L` 专属 PLA 预设（只有 PETG 系列），
> 所以 PLA/ABS/ASA/TPU 按「同熔池 92 mm³ 的 A1」取值；PETG 18 来自
> `Bambu PETG HF @BBL A2L`。这条口径写在 `rules/BambuRules.json` 的

> 官方 `Bambu Lab H2D.json` 这类**不带 nozzle 后缀**的文件是 `machine_model`

## 4. 同步 Bambu Studio 的自定义耗材

### 4.1 为什么

你「另存为自定义耗材」时，那支料带着自己的标定值：体积流量上限、风扇曲线、
流量比例、回抽长度。这些是厂商/你实测的，比内置五族通用基线准得多。

### 4.2 原理

Bambu 的耗材预设是**继承链 + 差分覆盖**：

```
%APPDATA%\BambuStudio\user\<user_id>\filament\彩格petg.json   ← 你另存的那支
  { "name": "彩格petg", "inherits": "Generic PETG @BBL P2S",
    "filament_max_volumetric_speed": ["9"], "nozzle_temperature": ["240"] }
        ↓
Generic PETG @BBL P2S  →  Generic PETG @base  →  fdm_filament_pet  →  fdm_filament_common
```

程序沿 `inherits` 向上合并，得到这支料**最终生效**的全部参数，
再抽出引擎要用的部分（流量上限、风扇、流量比、回抽、压力提前）。

### 4.3 操作

1. Bambu Studio 改好耗材 → 另存为自定义耗材。
2. 本程序点「同步 Bambu 自定义耗材」。
3. 下拉挑你那支（悬停看详情）。
4. 程序自动把「耗材类型」切到它所属的族，并用它的体积流量上限钳制所有速度。

**只读**：只读预设目录，不写、不改、不删 Bambu Studio 配置。

### 4.4 实测（本机 17 支）

```
PA6-CF三绿     ← ABS   流量上限 8 mm³/s    流量比 0.96    风扇 10~30%   265°C
多彩屋petg     ← PETG  流量上限 18 mm³/s   流量比 0.95    风扇 40~80%   255°C
R3Dpetg       ← PETG  流量上限 13 mm³/s   流量比 0.94    风扇 10~40%   255°C
菜多屋pla+…   ← PLA   流量上限 13.5 mm³/s 流量比 0.9702
```

### 4.5 数据位置

| 内容 | 位置 |
| --- | --- |
| 用户自定义耗材 | `%APPDATA%\BambuStudio\user\<user_id>\filament\*.json` |
| 系统内置预设 | `C:\Program Files\Bambu Studio\resources\profiles\BBL\filament\*.json` |
| OrcaSlicer | `%APPDATA%\OrcaSlicer\user\<user_id>\filament\*.json` |

## 5. 按模型几何细调（逐件）

### 5.1 事实：Bambu 的切片参数是整盘全局的

`Metadata/project_settings.config` 里没有「对象级切片参数覆盖」这一层——
工程里只有 `brim_object_gap`、`skirt_per_object`、`support_object_xy_distance`
这类全局相关项。所以「按模型针对性调参」不能给每个对象单独设值，
只能：**逐个对象判形状 → 每个形状给一套建议 → 合并成全局值时同一个键取最保守者**。

### 5.2 几何分析

从 `3D/3dmodel.model` 读三角形，散度定理算体积、逐面算法向与面积，
判定哪些朝下且够平的面需要支撑（**贴床底面不算**，否则大平板会被误判成 45% 悬垂）。

| 指标 | 含义 | 阈值 |
| --- | --- | --- |
| 细高比 | 高度 ÷ √底面积 | ≥ 2.6 判高瘦易晃 |
| 薄壁指数 | 表面积 ÷ 体积^(2/3) | 实心立方体约 6.0，> 9.5 判薄壁/镂空 |
| 支撑面占比 | 需支撑面积 ÷ 总表面积 | > 6% 考虑支撑，> 18% 支撑重 |
| 质心偏置 | 体积质心相对底面中心外偏 | > 0.35 提示 |

超 22 万三角形自动抽样（确定性伪随机抽样，不受面序影响），百毫秒级算完。
几何只读，`3D/3dmodel.model` 一个字节都不动。

### 5.3 两层几何规则

| 层 | 思路 | 覆盖 |
| --- | --- | --- |
| 形状原型层（`core/shape_rules.py`） | 10 个原型：细高 / 小脚高塔 / 扁平板 / 薄壁 / 长条 / 花瓶 / 大悬垂 / 实心块 / 小细节 / 通用 | 33 项 |
| 几何事实层（`core/geom_rules.py`） | 不按原型枚举，按几何事实枚举（21 个条件 × 139 条规则） | 99 项 |
| 支撑决策层（`core/support_plan.py`） | 悬垂占比 + 高度 + 判定角 → 支撑类型/疏密/间隙/贴面/树状分支 | 16 项 |

三层合起来覆盖切片工艺页 269 项里的 **262 项（97.4%）**。

界面上「逐件调参明细」逐对象列出：形状原型、判定依据、会被怎么调。
报告里也有同样的表格。

### 5.4 支撑由几何决定

| 判定 | 阈值 | 结果 |
| --- | --- | --- |
| 需不需要支撑 | 悬垂面占比 > 6% | 低于阈值不加支撑 |
| 支撑类型 | 悬垂 > 18% | `tree(auto)` → `tree(hybrid)` |
| 支撑疏密 | 悬垂 > 35% | 底纹间距 2.5 → 2.0 → 1.8 |
| 判定角 | 你的设置 25°（比几何建议 38° 更敏感） | 取你的 25°（更早触发，更安全） |
| 贴面间距 | 悬垂重 | 0.5 → 0.3 |
| 间隙 | 悬垂重 | 顶/底间隙 0.2 → 0.1 |
| 树状分支 | 高件 | 分支角 40°、直径 1.6、距离 6.0 |

**你的显式设置优先**：工程里开着支撑而几何判定不需要 → 不关掉它，只在说明里写清。
工程里没有模型信息 → 支撑一项都不碰。

### 5.5 测试模型

| --- | --- | --- |
| `shape_gear_small.3mf` | 36×36×8 齿轮 | 小件 + 薄壁（16.05） |
| `shape_vase_tall.3mf` | 60×60×190 | 高瘦（3.58）+ 高件 |

### 6.3 运算指令

| 键 | 含义 | 示例 |
| --- | --- | --- |
| `set` | 直接设为该值 | `{ "set": "top" }` |
| `mul` | 乘系数 | `{ "mul": 1.35 }` |
| `add` | 加偏移 | `{ "add": 0.05 }` |
| `min` | 下限（取更保守） | `{ "min": 3 }` |
| `max` | 上限（取更保守） | `{ "max": 10 }` |

执行顺序：`set` → `mul` → `add` → `min` → `max`。

`when` 支持：`printer`、`printer_group`、`filament`、`mode`、`nozzle_le`、`nozzle_ge`。

> **枚举键必须写成 `{"set": "gyroid"}`**，不能直接写字符串。
> `set` 是绝对值，会锁住这个键，后面的几何层不得再翻掉它。

## 7. 参数怎么算的

### 7.1 写入范围闸门

程序读到的 365 个可调参数按 Bambu Studio 的三个预设目录判定归属
（`profiles/BBL/process/` = 切片工艺页，`filament/` = 耗材页，`machine/` = 机器页）：

| 归属 | 数量 | 处理 |
| --- | --- | --- |
| 切片工艺 | 269 | **可写** |
| 耗材页 | 56 | 只读（值仍用来约束工艺参数） |
| 机器页 | 40 | 只读（值仍用来约束工艺参数） |

闸门在引擎最外层：`write_values` 里出现非工艺页键 = 测试直接失败。
界面上这些键列在「只读参照」里，能看到原值和为什么没改。

### 7.2 十层叠加

```
1.  defaults              通用基准（0.4 喷嘴，256 项；工程里已有的值当基准，不被覆盖）
2.  printers[].baseline   机型基线（X1 高速机架 / P1 中端 / P2 新平台 / A1 入门）
3.  filaments[].baseline  耗材基线（写相对操作：×0.95、上限…，不覆盖用户选择）
4.  modes[].ops           模式策略（均衡 9 / 强度 8 / 质量 19 项）
5.  filaments[].mode_ops  耗材 × 模式微调
6.  自定义耗材覆盖层       你同步的那支料的标定值（最可信）
7.  interactions[]        45 条交叉规则
8.  喷嘴等比缩放           层高 / 线宽 ×(喷嘴 ÷ 0.4)
9.  逐件几何层             形状原型 → 几何事实 → 支撑决策
10. 钳制                  参数区间 → 喷嘴约束 → 机型/真机上限 → 体积流量 → 时长上限
```

### 7.3 体积流量守卫

速度真正上限不是 mm/s，而是热端熔化能力：

```
最大速度 = 体积流量上限 ÷ (层高 × 线宽)
```

流量上限取值优先级：**工程里你标定的 `filament_max_volumetric_speed`
> 自定义耗材预设 > 官方「耗材 × 机型」标定 > 规则库基线**。
工程里的值是「这台机器 + 这卷料」实测标定的，比官方通用标定更贴近，
直接采用；只有当它明显高于官方标定（>1.3 倍）时才提示复核。

官方标定实测值（mm³/s）：PLA 21 / PETG 13（X1C·P2S）、9（A1）、8（P1）/
ABS 16 / ASA 18 / TPU 3.6。

### 7.4 时长估算

```
指数 = 层数 × 每层时间（墙路径 ÷ 速度 + 填充路径 ÷ 速度 + 空走 + 换层固定开销）
       + 顶底实心层（与层高无关）
       + 首层慢速额外时间（随层高缩放）
       再乘加速度修正系数
```

实测敏感度：层高减半 +74%、墙层 +1 圈 +20%、密度 15→30% +6%、
外壁速度减半 +27%、速度全翻倍 −45%、加速度 10000→5000 +5%。
文案写「约 ±X%（±5%，仅相对估算）」，精确值以切片结果为准。

### 7.5 时长上限

勾选后（默认 25%）超限时按代价从小到大回退：
层高 → 填充密度 → 顶底壳层数 → 墙层数 → 各段速度。
回退后重新过一遍全部硬约束（含喷嘴层高窗口），不会写出非法值。达不成就明确告警。

### 7.1 按模型实测尺寸做定量推导（不是套模板）

第 5 章的「形状原型」是定性判断（高瘦 / 平板 / 薄壁…）。从这一版起还多了一层
**定量推导**：直接从模型网格量出尺寸，代进公式算出参数值，公式写进报告让人能手算复核。

| 规则 | 实测什么 | 公式 | 只在哪档生效 |
| --- | --- | --- | --- |
| R1 墙圈数 | 最小壁厚 `t_min` | `ceil(t_min ÷ 线宽)`，上限 6 | 仅**强度优先**（其它档堆墙＝拿时间换测不出的刚度） |
| R2 层高上限 | 最薄特征 `t_min` | `上限 = t_min ÷ 2`（低于当前层高才写，下限 0.08） | 全部 |
| R3 首层速度 | 首层接触面积 | `55 − 30 × min(1, 面积 ÷ 62500)`，向下取整到 5 | 全部 |
| R4 顶/底壳层 | 顶盖占比 `top_cap_ratio` | 顶 `ceil(目标 ÷ 层高)`（密封面 0.8 / 开放面 0.6）、底 `ceil(0.6 ÷ 层高)`，各夹 3~8 | 全部 |
| R5 填充密度 | 细高比、体积 | `25% + 8%（细高比≥2.6）+ 5%（体积≥200 cm³）` | 仅强度优先 |
| R6 接缝位置 | 顶盖占比 / 扁平度 / 长宽比 / 尖端比 | 大平顶 → `back`；细高 → `aligned`；尖端 → `nearest` | 全部 |

薄壳判定用 `fill_ratio < 0.55`：实心块的「壁厚」会量成 `边长/3`，直接除线宽会得到
荒谬的圈数（一个 20 mm 实心立方体会算出 44 圈墙），所以要挡掉。

UI 的「按模型实测尺寸推导」表格和报告的「按模型实测尺寸推导」章节，逐条列出
`指标 / 实测 / 公式 / 结论`。例：

```
层高上限   layer_height   实测 最薄特征 2.84 mm ／ 当前层高 0.20 mm
          公式 上限 = 2.84 ÷ 2 = 1.42       结论 层高未超过特征一半，不改
首层速度   initial_layer_speed  实测 首层接触面积 73 mm²（占比 0%）
          公式 55 − 30 × 面积占比           结论 算出上限 55 ≥ 当前 50，不改
```

### 7.2 叠乘总闸（同一参数被多层连乘时的刹车）

十层叠加里，同一个键可能被「机型基线 × 耗材基线 × 模式 × 交叉规则 × 形状 × 几何」
连乘，越乘越离谱（早期版本把 `travel_speed` 从 1000 一路乘到 207 mm/s）。

现在引擎记录**每个键的累计倍率**，超出 `options.mul_total_band`（默认 `[0.6, 1.8]`）
就把这一次的倍率打折到边界，并在警告里写明「本来会到 ×N，已压到 ×M」。

模式档自己的 `set`/`mul` 不过闸（`band=False`）——模式档的 ×0.4 是作者意图，
不该被当成误伤。

### 7.5 喷嘴流量同步（换喷嘴必须换流量）

Bambu 官方的 `filament_max_volumetric_speed` 是**按喷嘴**给的，不是按耗材：

| 耗材 | 机型组 | 0.2 喷嘴 | 0.4 喷嘴 | 0.6 喷嘴 | 0.8 喷嘴 |
| --- | --- | --- | --- | --- | --- |
| PLA | X1 / P1 / P2 / A1 | 2 | 21 | 21 | 21 |
| PLA | H2 | 2 | 25 | 30 | 30 |
| PETG | X1 / P1 | 1 | 13 | 13 | 16 |
| PETG | P2 | 1 | 13 | 16 | 16 |
| PETG | A1 | 1 | 9 | 9 | 12 |
| PETG | H2 | 1 | 13 | 16 | 16 |
| ABS | X1 / P1 / P2 | 2 | 16 | 16 | 18 |
| ABS | A1 | 2 | 16 | 16 | 16 |
| ABS / ASA | H2 | 2 | 20 | 25 | 25 |
| ASA | X1 / P1 / P2 / A1 | 2 | 18 | 18 | 18 |
| TPU | 全系 | 3.6 | 3.6 | 3.6 | 3.6 |

（数据由 `tools/_dump_flow_matrix2.py` 从官方预设读出，写进 `rules/BambuRules.json` 的
`nozzle_flow` 段。改喷嘴时引擎读它折算。）

为什么必须同步：0.2 喷嘴的熔池每秒只能熔 1 mm³ 料。把 0.4 的 13 mm³/s 套到 0.2 上，
算出来的内壁 200 mm/s 是物理跑不到的 —— 实际表现是挤出不足、表面糊、严重时堵料。
反过来把 0.2 的 1 套到 0.8 上，会把 0.8 的产能白白压掉 90%。

引擎的处理（`core/nozzle_flow.py` + `core/rules_engine.py` 的 `_clamp_flow`）：

1. 工程里的 `filament_max_volumetric_speed` 是按**工程那个喷嘴**标定的；
2. 你在下拉里换了喷嘴 → 先按官方流量比把工程标定值折算到新喷嘴；
3. 再与新喷嘴的官方上限**取小**；
4. 都记一条警告，写清「18 mm³/s 是按 0.4 标的 → 折算到 0.2 是 1.4 → 与官方 1 取小 → 按 1.0 算」。

实测（鱼缸温度计支架，P2S + PETG，工程标定 18 mm³/s、工程喷嘴 0.4）：

| 你在下拉里选 | 采用流量上限 | 外壁 | 内壁 | 填充 | 层高 | 线宽 |
| --- | --- | --- | --- | --- | --- | --- |
| 0.2 mm | **1.0** mm³/s | 47.6 | 44.4 | 44.4 | 0.10 | 0.21 |
| 0.4 mm（= 工程值） | 18.0 mm³/s | 161.5 | 200.0 | 200.0 | 0.20 | 0.42 |
| 0.6 mm | **16.0** mm³/s | 90.7 | 84.7 | 84.7 | 0.28 | 0.63 |
| 0.8 mm | **16.0** mm³/s | 68.0 | 63.5 | 63.5 | 0.28 | 0.84 |

同喷嘴时仍以你工程里的实测标定为准（那是这台机器 + 这卷料的真实值），
只有换了喷嘴才会被官方上限压住 —— 因为你的标定只对原喷嘴成立。

验证命令：

```bash
python tools/check_nozzle_flow.py      # 四个喷嘴各跑一遍，打印流量上限与关键速度
python -m pytest tests/test_nozzle_flow.py -q
```

### 7.3 时长预算（每档自带，写在 JSON 里）

| 模式 | `time_budget_pct` | 含义 |
| --- | --- | --- |
| 强度优先 | 200 | 加墙加密度本来就慢，允许到 2 倍 |
| 表面质量 | 170 | 慢一倍多是合理的，再多就退填充/速度 |
| 均衡 | 40 | 硬约束，最多慢 40% |
| 草稿 | 10 | 「快」的档，几乎不许变慢 |
| 精细 / 超精细 | `null` | 不限（靠小层高换质量，拉高层高会毁掉这一档） |

超预算时按**代价最小**的顺序回退：填充密度 → 顶底壳层 → 墙圈数 → 提回速度 →
提回加速度。三条硬规矩：

1. **每一步改动必须真的让时间变短才留下**，否则撤回换下一步（体积流量受限时，
   抬层高反而压低可挤出速度，越调越慢）；
2. **强度档不动墙圈数**（加墙是这个档的存在意义，砍回 3 圈等于偷偷变成均衡），
   层高最多抬到 0.24；
3. **草稿档墙圈数一律不超过用户原值**（多一圈墙＝多一倍墙路径）。

### 7.4 时长估算为什么现在可信了

旧模型拿「用户写的速度」当基准。可是工程里 `inner_wall_speed = 300`、`PETG 流量 18 mm³/s`，
0.2 mm 层高 × 0.42 mm 线宽下物理上限只有 `18 ÷ 0.084 ≈ 214 mm/s`，
300 是跑不到的。拿 300 当基准，就会把所有优化都算成「大幅变慢」。

现在估算器接受 `flow_limit`，两侧都按 `min(写定速度, 流量÷(层高×线宽))` 算，
所以「原参数」和「新参数」在同一条物理线上比较。

### 7.6 打印板同步（板型 / 板面 / 放得下吗）

工程里带着三组和板有关的信息，本程序全部读、全部判，板型和板面本身只读不写：

| 来自哪 | 键 | 例子 |
| --- | --- | --- |
| 打印页 | `curr_bed_type` | `Supertack Plate` |
| 耗材页 | `cool_plate_temp` / `eng_plate_temp` / `hot_plate_temp` / `textured_plate_temp` / `supertack_plate_temp` | 本工程 PETG：0 / 70 / 70 / 80 / 60 |
| 机器页 | `printable_area` / `printable_height` / `wrapping_exclude_area` | 256×256×256，前方禁打区 1 块 |

**兼容性判据直接用官方数据**：官方 filament 预设里，某条料在某块板上不可用时，
那块板的温度就是 `0`。本工程 PETG 的 `cool_plate_temp = 0` —— 说明低温板不能跑 PETG。
所以看到 0 就报硬警告，不用自己编一张兼容表。

引擎第 7.8 层做四件事：

1. 认板型：`core/plate.py` 把 `curr_bed_type` 对应到官方温度键（「光面 PEI」复用纹理板温度键）；
2. 判兼容：温度 `0` → 硬警告「这条料不能在这个板上打印」；
3. 判板面：工程 `printable_area` 与机型官方板面对不上就报警 —— 这是**机型识别错**的强信号
   （例如识别成 A1 mini 但工程板面是 256×256，A1 mini 只有 180×180）；
4. 判放得下：用**你选的那台机器**的官方板面比每件的 `size_x × size_y`，两个方向都试（含旋转 90°）。

机型官方板面（写进 `rules/BambuRules.json` 的 `printers[*].bed`）：

| 机型 | 板面 | 成型高度 |
| --- | --- | --- |
| X1 / X1C / X1E / P1P / P1S / P2S / P2P / A1 | 256 × 256 | 256 |
| A1 mini | **180 × 180** | 180 |
| H2D / H2D Pro | **350 × 320** | 325 |
| H2S | **340 × 320** | 340 |

板型相关工艺微调写在 `rules/BambuRules.json` 的 `plates.items.<板型>.process`，
默认只给一条（超粘板 `elefant_foot_compensation ≥ 0.15`，因为粘得越牢越容易鼓边）。
注意：`brim_width` 在 schema 里是 `preserve=True`（你自己定的值不许动），板层写它会被静默跳过 ——
所以「超粘板别加宽裙边」这类建议以 `advice` 文字形式进日志，不动参数。

验证：

```bash

python -m pytest tests/test_plate.py -q
```

## 7.9 热端流量类型（标准流量 / 高流量 / E3D 高流量）

### 为什么它不能只当标签

三种热端的差别是**熔化能力**，不是精度。同一个 0.4 喷嘴，标准热端官方标定 PETG 13 mm³/s，
高流量热端能推得更多。如果只把它显示在界面上、不影响计算，高流量热端就会被按标准热端的
流量上限钳着跑，白买了。

### 怎么识别

工程里表达这件事的键有六个（都在机器页，只读）：

| 键 | 典型值 | 说明 |
| --- | --- | --- |
| `nozzle_volume_type` | `["Standard"]` | 首选判据 |
| `default_nozzle_volume_type` | `["Standard"]` | 兜底 |
| `extruder_nozzle_stats_new` | `["Standard#1"]` | 带数量后缀 |
| `extruder_nozzle_stats` | `["Standard#1"]` | 同上 |
| `printer_extruder_variant` | `["Direct Drive Standard", "Direct Drive High Flow", ...]` | 整机支持的变体 |
| `print_extruder_variant` | 同上 | 本工程用的变体 |
| `nozzle_volume` | `["110","110","110"]` | 熔池体积，随类型变化 |

识别顺序就是上表顺序，命中即停；`core/hotend.py` 的 `detect()` 会把「依据哪个键、原值是什么」
一起记下来，显示在界面与报告里（`依据 nozzle_volume_type = 'Standard'`），方便你判断识别对不对。

### 怎么算

规则库 `hotend_flow.types` 只给一个倍率 `volumetric_mul`：

```json
"hotend_flow": {
  "types": {
    "standard": { "label": "标准流量",   "volumetric_mul": 1.0 },
    "high":     { "label": "高流量",     "volumetric_mul": 1.35 },
    "e3d":      { "label": "E3D 高流量", "volumetric_mul": 1.55 }
  }
}
```

- 倍率**只会放宽、不会收紧**（`factor()` 强制 ≥ 1.0）：识别不出来时按 1.0，不会把高流量热端压回去。
- 它作用在**体积流量上限**上，不额外乘速度。高流量省下的时间由「流量上限 ↑ → `_clamp_flow`
  允许更快的速度」自动体现；再单独乘速度倍率等于同一件事算两遍，会让速度越过机器上限，
  也会把时长估算压低得不真实。
- 工程里的 `filament_max_volumetric_speed` 是**在工程那根热端上标出来的**。如果你在下拉里
  改成高流量（= 换了热端），引擎会按两根热端的比例折算这个标定值，并给一条警告提醒你
  换热端后重新做一次流量标定。

### 实测（真实工程 P2S + PETG，工程标定 18 mm³/s）

| 下拉选择 | 流量上限 | 内壁速度 | 层高 |
| --- | --- | --- | --- |
| 自动 / 标准流量 | 18.0 | 200.0 | 0.20 |
| 高流量 | 24.3 | 234.8 | 0.23 |
| E3D 高流量 | 27.9 | 269.6 | 0.23 |

## 7.10 写入纪律：只写这一份 3mf，不碰拓竹的任何预设

这条是硬约束，不是承诺。四道闸口都在代码里：

| 闸口 | 位置 | 拦什么 |
| --- | --- | --- |
| 参数范围闸 | `core/scope.py` 的 `ScopePolicy.allows()` | 只放行切片工艺页的键；耗材页、机器页的键一律不写（只读参照，用来约束工艺页的上下限） |
| 路径闸 | `core/safety.py` 的 `guard_target()` | 目标路径若落在 `%APPDATA%\BambuStudio\user\{filament,process,machine,printer}` 或安装目录 `resources\profiles\` 下（本机实测 42 个预设目录、2750 个 json），直接抛异常拒绝写；后缀不在 `.3mf/.bambu/.md/.txt/.json/.log` 内也拒绝 |
| 预设指纹闸 | `safety.fingerprint()` + `diff_fingerprint()` | 保存前后各拍一次全量指纹（mtime_ns + size 的 sha1），有变化就在日志里告警 |
| 写出自检闸 | `safety.self_check()` | 存完立刻把文件重新打开，把 `project_settings.config` 里每个写入项和内存里的结果逐条比，不一致就列出来 |

### 值一律写成字符串

Bambu 的 `project_settings.config` 里所有值都是字符串（`'["179", "500", "500"]'`、`'0.24'`）。
引擎内部为了算数会把它们变成数字，写回时必须还原成字符串：`core/threemf.py` 的
`studio_settings()` 统一做这件事。以前少了这一步，数字型值写进去可能被 Studio 的解析器
整份拒绝——表现出来的就是「文件能打开，参数没变」。

### 工艺档名默认不动

`print_settings_id` 默认保持原样（`0.20mm Standard @BBL P2S`）。Studio 打开工程时会按这个名字
去盘上找同名预设，如果你担心它用预设值盖掉文件里的值，可以勾保存区的
**「把工艺档标为自定义（仅当 Studio 打开后没反映改动时才勾）」**——它会把 3mf 里这一行改成
`0.20mm Standard @BBL P2S - Smart Tuner`，Studio 找不到同名预设，只能采用文件里的参数。

这个开关只改工程文件内部的一行元数据：
- 不写 Bambu Studio 的任何预设文件；
- 不动 `filament_settings_id` / `printer_settings_id`（那两个决定喷头与 AMS 映射，动了会出别的问题）；
- 幂等：已经带 ` - Smart Tuner` 后缀就不再叠加。

### 耗材参数为什么改不了

耗材页（风扇、回抽、流量比、压力提前、板温）属于「这一卷料」的属性，写进工程就等于改了
你的耗材配置，跟「只改工艺」冲突。所以这些键一律只读：引擎会读它们的值来约束工艺参数
（例如按风扇设定判断悬垂能不能堆料、按回抽设定判断拉丝风险），但一个字都不写回。

想改耗材参数，请在 Bambu Studio 里改，并确认它只作用于当前工程。

## 7.13 裙边与支撑：按实测尺寸算，不按原型猜

这两块原来是「按形状原型给个固定值」（细高件给 8 mm 裙边、悬垂件给密支撑），
同一个原型里的件差别很大——10×10×120 的细杆和 40×40×120 的方块都被判成「细高件」。
现在改成**先量、再算**，公式写在界面「按模型实测尺寸推导」表里，每一行都能手算复核。

### 裙边：倾覆指数

```
倾覆指数 = 高 ÷ √底面积 × (1 + 重心偏移比)
重心偏移比 = 重心偏移 ÷ 长边（夹到 0~1）
```

底面积取 `model_analysis` 里最窄那段剖面的包围盒（真正着地的面积，不是最大投影）。

| 倾覆指数 | 裙边宽度 | 典型 |
| --- | --- | --- |
| ≥ 8 | 10 mm | 10×10×100 的细杆（指数 10） |
| ≥ 5 | 8 mm | 20×20×120（6.0）、细高支架 |
| ≥ 3 | 5 mm | 30×30×90（3.0） |
| ≥ 1.8 | 3 mm | 略微偏高的件 |
| < 1.8 | 不动 | 平板、矮块 |

再按耗材修正：ABS/ASA ×1.25（收缩最凶）、PETG ×1.0、PLA ×1.0、TPU ×0.75（撕不下来）；
宽度取整到 0.5 mm，上限 20 mm。小件（体积 < 8 cm³ 或最短边 < 12 mm）保底 3 mm。

同时给 `brim_type = outer_only`（只在外圈，不钻到模型底下）和
`brim_object_gap`（PLA 0.28 / PETG 0.32 / ABS·ASA 0.30 / TPU 0.35，好撕）。

三条保护：
- 工程里原本 `brim_type = no_brim`（明确不要裙边）→ 一个字都不改；
- 工程里原本裙边比算出来的更宽 → 保留原值，不往回压；
- 倾覆指数低于 1.8 → 保留原值。

### 支撑：按悬垂量和高度分级

| 参数 | 判据 | 取值 |
| --- | --- | --- |
| `support_base_pattern_spacing`（密度） | 悬垂总面积 | ≥4000 → 1.6；≥1500 → 2.0；≥400 → 2.5；其余 3.0 mm |
| `support_top_z_distance`（顶面间隙） | 层高 | 层高 × 0.7，夹 0.12~0.30 mm |
| `support_object_xy_distance`（水平安全距） | 细高比 / 高 / 底面积 | 细高比≥3 或高≥120 → 0.8；底面积<600 mm² → 0.9；否则 0.5 |
| `support_type` / `support_style`（形态） | 细高比 / 悬垂量 | 细高比≥3.2 或高≥150 → `tree(auto)`，细高比≥3.5 用 `tree_strong`；大面积低矮悬垂 → `normal(auto)` + `grid` |
| `support_interface_spacing`（界面层） | 悬垂总面积 | ≥1500 → 0.5（顶面平整）；其余 0.7（好撕） |

只在这些前提下动手：`enable_support` 已经开着（要不要支撑仍由 `support_plan` 按判定角决定，
这里只决定「开多大、离多远、长什么样」）。

### 现在裙边/支撑只由一个地方决定

原来 `shape_rules` 的 10 个原型里硬写了 15 条 `brim_width`（8/10/12/6/7/5），
`geom_rules` 还有两条 `min` 下限，三方互相顶。现在：
- `shape_rules` 里 15 条写死的 brim_width 全部删除；
- `geom_rules` 的两条 brim 下限改成占位（`{"mul": 1.0}`）；
- **裙边宽度只有 `core/adhesion.py` 说了算**，支撑密度/间隙/形态只有 `core/support_model.py` 说了算。

改完实测（鱼缸温度计支架，32×45×54、底面积 73 mm²、细高比 6.36）：

```
倾覆指数 6.39 → 基准 8 mm × PETG 1.0 = 8 mm（约 19 圈，间隙 0.32 mm）
支撑：线距 2.5 mm（悬垂 644 mm²）／顶面间隙 0.14 mm（层高 0.2×0.7）／
      水平安全距 0.9 mm（细高比 6.36 + 底面积 73 mm²）／树状支撑 tree_strong
```

## 7.15 交替额外墙层与「墙层数 / 垂直外壳厚度」的成套要求

在 Bambu Studio 里勾上 **交替额外墙层（alternate_extra_wall）** 后打开工程，Studio 会弹：

```
为使交替额外墙层正常工作，建议进行以下调整：
- 将确保垂直外壳厚度设为「部分」
- 将墙层数设为 2
是 - 应用修改并保持交替额外墙层启用
否 - 保持当前设置并启用交替额外墙层
```

这不是我们写坏了文件，是 Studio 对这三个键的一致性要求：

| 键 | 要求 |
| --- | --- |
| `alternate_extra_wall` | 1（开启） |
| `ensure_vertical_shell_thickness` | `partial`（部分）|
| `wall_loops` | 2 |

而强度档会把 `wall_loops` 从 2 提到 4~6 圈（细高件还按壁厚算到 6），必然撞上这条。

### 现在的处理（`core/wall_compat.py`，引擎第 7.77 层）

| 情况 | 处理 | 说明 |
| --- | --- | --- |
| 工程开着交替额外墙 + 本档把墙层数提到 >2 | **写出 `alternate_extra_wall = 0`** 并在日志给黄色警告 | 4 圈以上时交替额外墙的增量已经很小，外壳强度由墙圈数本身提供；想保留这个功能就用均衡档（不动墙层数） |
| 工程开着交替额外墙 + 墙层数保持 2 | **写出 `ensure_vertical_shell_thickness = partial`**，附说明 | 补齐 Studio 要求的另一半，打开工程不再弹窗 |
| 工程本来就成套（已是 partial） | 不动，只记一条 note | |
| 工程没开这个功能 | 三个键都不碰 | 原有行为不变 |

对应测试：`tests/test_hotend_safety.py::TestWallCompat`（6 项），覆盖上面四种情况 + schema 里必须有 `partial` 选项 + 引擎端到端写 0 并告警。

### 遇到这个弹窗怎么选

- 点 **是**：Studio 会把垂直外壳厚度改成「部分」、墙层数改回 **2**，等于把你刚调好的强度档墙圈数冲掉，不推荐。
- 点 **否**：保留你当前设置，交替额外墙继续开着，但 Studio 提示仍会在下次打开时出现。
- 更省事的做法：重新用本工具跑一遍（现在会自动把 `alternate_extra_wall` 写 0），或者在 Studio 里自己把那勾去掉。

### schema 里的选项修正

`ensure_vertical_shell_thickness` 的合法值是 `enabled / disabled / partial`（原来写成 `ensure_all` 是错的，Bambu 2.x 根本没有这个值），已修正，否则引擎想写「部分」会被自己的区间检查拦下来。

## 7.16 速度类参数为什么以前「改了没生效」——按热端变体分槽

Bambu 的这批键在工程里是**数组**，一个槽位对应一种热端：

| 键 | 工程里的值 | 含义 |
| --- | --- | --- |
| `outer_wall_speed` | `["200", "500", "500"]` | 标准流量 / 高流量 / E3D 高流量 |
| `inner_wall_speed` | `["300", "600", "600"]` | 同上 |
| `travel_speed` | `["1000", "1000", "1000"]` | 同上 |
| `default_acceleration` | `["10000", "10000", "10000"]` | 同上 |

槽位数来自工程里的 `print_extruder_variant`：

```
["Direct Drive Standard", "Direct Drive High Flow", "Direct Drive E3D High Flow"]   → 3 槽
```

**Bambu Studio 显示的是「当前所选热端」那一槽的值。** 以前本程序只改第 0 槽，
如果你的 Studio 里喷嘴那一栏选的是「高流量」，它读的是第 1 槽 = 500，
于是现象就是：表格里写着 `外壁速度 200 → 124`，Studio 里还是 500，看起来完全没改。

### 现在的做法

`core/schema.py` 的 `set_variant_slots(n)`：引擎在每次优化开头按
`hotend.slot_count(工程)` 告诉她本工程有几个变体槽位；写回时对
**槽位数 == 变体数** 的数组参数（速度、加速度、流量这类）**每一槽都写成同一个优化值**：

```
outer_wall_speed: ["200", "500", "500"]  →  ["162", "162", "162"]
```

为什么写同一个值而不是按比例放大：高流量热端「能跑更快」不等于「应该跑更快」。
本程序的优化目标是表面质量 / 强度 / 时间预算，与热端类型无关；写保守值最安全，
而且无论你在 Studio 里选哪种热端，看到的都是真正生效的那个数。

没有变体列表的工程（`print_extruder_variant` 只有 1 项或不存在）仍然只改第 0 槽，
不会把其它喷嘴/耗材的设定顺手改掉。

### 自查命令

```powershell
python tools/check_slot_write.py
```

输出会逐键打印「源 / 出」两个数组，确认三个槽位都被写成同一个值：

```
outer_wall_speed   源=['200', '500', '500']   出=['162', '162', '162']
inner_wall_speed   源=['300', '600', '600']   出=['200', '200', '200']
travel_speed       源=['1000', '1000', '1000'] 出=['600', '600', '600']
```

### 与「只动工艺页」的关系

这次改动仍然只碰工艺页的键（`outer_wall_speed` 等都是 process 页），
耗材页、机器页一个都没动；变的只是「同一个工艺键写几个槽位」。

### 7.18 支撑的「开不开」交给你：模式区的「支撑」下拉

支撑分两件事，本程序只自动做前一件：

| 事情 | 谁决定 |
| --- | --- |
| 要不要开、用多少料、离多远、长什么样、多快 | 本程序按模型实测尺寸算（见 §7.17） |
| 支撑具体落在哪个位置 | **只能你在 Bambu Studio 里判断**（用「支撑/阻止支撑」刷子） |

所以模式区多了一个下拉，三档：

| 档位 | 行为 |
| --- | --- |
| **自动（按模型判断）** 默认 | 按悬垂判断要不要开；**如果工程里原本是关的、这次替你打开了，日志会出一条黄警告**，提醒你去 Studio 看一眼落点 |
| **强制开启** | 不管工程原来怎样都开，并按模型算全套参数 |
| **强制关闭** | 一个 `support_*` 键都不写，悬垂部分你自己处理 |

对应命令行是 `--support auto|on|off`。

> 自动档的那条提醒原文：已自动开启支撑（工程里原本是关的，模型有悬垂）：请到 Bambu Studio 里看一眼支撑落点——某些位置不该有支撑就用「支撑/阻止支撑」刷子手动拦掉，或在模式区的「支撑」下拉里选「强制关闭」。自动档只管开不开和用多少料，支撑落在哪里只有你能判断。

### 7.19 右上角的「☕ 投喂作者」

标签页右上角常驻一个按钮，点开是收款码弹窗。它只做一件事：显示 `assets/donate.png`。
图片走 `_asset_path()` 的三级查找（EXE 同目录 `assets/` → 打包内 `_MEIPASS/assets/` → 源码 `assets/`），
换二维码只要替换这个文件，不用改代码：

```

```

## 9. 已知限制

### 9.1 不改的参数

见第 12 章，逐类列出不改的键及原因。三句话：

- **温度类**（喷头/热床/腔体）：属耗材预设，跨环境差异大，写死会废件。
- **硬件类**（机器限位、喷嘴型号、可打印区域）：改了就与真机不符。
- **元数据/G 代码/AMS 槽位**：不是工艺参数，改了破坏结构或换料逻辑。

### 9.2 其他

- 不支持 `.gcode.3mf`（已切片包）：没有完整工程参数，需重新保存工程。
- 多耗材/多喷嘴只按第一种耗材、第一个喷嘴算。
- 时长是相对估算（±5%），不是精确值。
- 几何自适应基于几何统计，不做逐层切片仿真；极端模型（大量桥接、螺旋花瓶模式、多材料混打）只能给方向性建议。
- 自定义耗材父预设缺失时退化到按族基线处理，列表里标 ⚠。
- `gap_fill_speed` 是早期误写的键名，官方真实键名是 `gap_infill_speed`（数组型），已统一为后者。

### 9.3 安全性

- 原文件绝不覆盖：输出等于源文件时直接报错。
- 内存算完 → 写临时文件 → 原子替换，中途失败不留半个坏 3mf。
- 顺手清过期切片结果（`slice_info.config`、`*.gcode`），避免显示旧时长。
- 只读几何，绝不改 `3D/3dmodel.model`。
- 自定义耗材同步只读预设目录。

## 10. 报错排查

### 10.1 加载

| 提示 | 原因 | 处理 |
| --- | --- | --- |
| `不是有效的 3mf（zip）包` | 文件损坏或不是 3mf | 回 Bambu Studio 重新保存 |
| `包里没有 Metadata/project_settings.config` | 导出的是 G-code 或纯模型包 | 用「保存工程」 |
| `project_settings.config 不是合法 JSON` | 被别的工具改坏 | 重新保存 |
| `只支持 .3mf / .bambu 工程文件` | 后缀不对 | 改后缀或重导 |

### 10.2 识别

| 现象 | 原因 | 处理 |
| --- | --- | --- |
| 黄字「未能识别机型」 | `printer_model` 是自定义名 | 下拉手选 |
| 耗材识别成 GENERIC | `filament_type` 为空 | 手选族 |
| 喷嘴显示 0.4 但不是 | 没存 `nozzle_diameter` | 手选 |
| 同步后带 ⚠ | 父预设找不到 | 确认 Bambu Studio 装在默认路径 |

### 10.3 优化

| 现象 | 原因 | 处理 |
| --- | --- | --- |
| 改动 0 项 | 参数已是最优值 | 正常，换模式或改规则库 |
| 大量「受体积流量上限约束」 | 该料熔化能力有限 | 正常保护，想更快换高流量热端 |
| 「工程里记录的最大速度 1000 高于机型上限 600」 | 工程机器预设被改过，或机型识别错 | 确认机型选择 |
| 「工程里你标定的热端流量 18 明显高于官方标定 13」 | 你换了高流量热端或好料 | 确认即可，程序按你的值算 |
| 「时长上限无法达到」 | 物理极限 | 接受，或加大层高/降填充/换热端 |
| 同一参数多原因 | 多层规则都动了它 | 正常，`→` 就是叠加过程 |
| 支撑参数变了但没支撑 | 「启用支撑」开关要你自己勾 | 见 12.3 |

### 10.4 保存

| 现象 | 原因 | 处理 |
| --- | --- | --- |
| `输出路径不能和原工程相同` | 输出填成源文件 | 换名字（程序也会自动加时间戳） |
| Bambu Studio 里参数没变 | 打开旧文件，或又在工程设置里改了 | 确认开的是 `_optimized_` 那个 |
| 没有切片预览 | 正常，旧切片结果被清了 | 在 Studio 里点「切片」 |

### 10.5 打包

| 现象 | 原因 | 处理 |

| 中文变方块 | 缺中文字体 | 装微软雅黑 |
| 体积太大 | 打进 PyQt/WebEngine | 用提供 `.spec`，已排除大模块 |

## 14. 和官方同档预设逐项对标的结果

「这个软件到底有没有用」不能靠感觉，工具 `tools/compare_with_official.py`
把本软件的输出和 Bambu Studio 官方同档预设逐项对齐（官方没给某机型出这一档时
回退到 `@BBL X1C` 的同档预设，那是官方唯一给出的全套标定）：

```bash
python tools/compare_with_official.py                     # 六档全跑
python tools/compare_with_official.py 工程.3mf --mode=balanced
```

实测（`鱼缸温度计支架.3mf`，P2S + PETG，594 键）：

| 模式 | 官方对标预设 | 写入 | 与官方一致 | 有差异 | 官方无该键 | 时长 |
| --- | --- | --- | --- | --- | --- | --- |
| 强度优先 | 0.20mm Strength @BBL X1C | 37 | 1 | 35 | 1 | +125.1% |
| 表面质量 | 0.16mm High Quality @BBL P2S | 40 | 7 | 28 | 5 | +57.4% |
| 均衡 | 0.20mm Standard @BBL P2S | 25 | 2 | 22 | 1 | +40.7% |
| 草稿 | 0.24mm Draft @BBL X1C | 23 | 3 | 20 | 0 | +15.2% |
| 精细 | 0.12mm Fine @BBL X1C | 45 | 7 | 34 | 4 | +150.4% |
| 超精细 | 0.08mm Extra Fine @BBL X1C | 46 | 10 | 32 | 4 | +230.9% |

**怎么读这张表**：差异不是「谁对谁错」，而是「本软件在你这个工程上做了官方预设
不会做的针对性调整」，每一条差异在报告里都带理由链。典型的四类差异：

1. **体积流量钳制**：官方预设的内壁 300 mm/s 在 PETG 13~18 mm³/s 下跑不到，
   本软件按物理上限写 174~214；官方的实际切片也会被 Studio 内部限流器降速，
   只是它不写进参数；
2. **继承工程原值**：官方预设是「全新工程」的默认值，而你的工程已经有你调过的
   支撑/层高/密度，本软件以你的值为基准，不推翻；
3. **按模型几何**：细高件的加速度、扁平件的裙边、悬垂件的支撑密度——
   官方预设不知道你打的是什么；
4. **按真机上限**：工程 machine 页记录的速度/加速度/流量才是这台机器，
   官方预设是机型系列的通用值。

`官方无该键` 那一列是 Bambu 新版专有键（`mmu_segmented_region_*`、
`start_end_points`、`counterbore_hole_bridging` 等），官方 0.20mm Standard
参照预设里根本不出现，无法对标，只能按区间与工程现值处理。

## 15. 社区经验来源

参数策略以**官方预设差分 + 物理公式**为主，社区经验只在校验和「耗材页建议」上用：

| 结论 | 社区/厂商口径 | 在本项目怎么落地 |
| --- | --- | --- |
| PETG 风扇 20~50%，超过 50% 层间粘合明显下降 | [Overture PETG 指南](https://overture3d.com/blogs/overture-blogs/petg-print-settings-guide)（230~250 ℃ / 热床 80~90 ℃ / 风扇 30~50%）、[Raise3D PETG 指南](https://www.raise3d.com/blog/petg-3d-printing/)（前几层后 20~40%）、[知乎 PETG 关键指南](https://zhuanlan.zhihu.com/p/1916783287046762501)（20~50%） | 风扇属**耗材页**，本程序只读不改；PETG 相关的提示里写明「风扇要你自己在耗材设置里确认，超过 50% 会掉层间强度」 |
| PETG 慢空走会加剧拉丝（喷嘴在途中持续出料） | 同上几篇的 stringing 章节一致结论 | 早期版本把 PETG 空走压到 250 mm/s，已**删除**这条改成提示：空走保机型高速，治拉丝靠回抽/擦嘴/Z hop（耗材页） |
| 层间强度主要靠温度与流量，不靠加墙 | 各厂 PETG/ABS 指南的共同结论 | 墙圈数只在**强度档**按实测壁厚加，其它档保持官方 2 圈，避免拿时间换测不出的刚度 |

耗材温度/风扇/回抽这些**真正决定层间强度的项都在耗材页**，被只读闸门挡住，
所以报告里单列「只读参数」章节提醒你回 Bambu Studio 自己确认——这是刻意的设计，
不是漏掉。

## 7.17 支撑：按模型实测尺寸算，且只有一个模块说了算

以前支撑参数被三个地方同时写（形状原型、几何规则、支撑策略），结果出现两种毛病：
**支撑明明没开，却改了支撑间隙**；以及同一个键被三方各写一次、互相覆盖。

现在分工是硬边界：

| 模块 | 只负责 | 产出 |
| --- | --- | --- |
| `core/support_plan.py` | 要不要支撑、悬垂判定角多少 | `enable_support`、`support_threshold_angle` 两个键 |
| `core/support_model.py` | 用多少料、离多远、长什么样、多快 | 全部支撑定量键 |
| `core/shape_rules.py` / `core/geom_rules.py` | 不再写任何 `support_*` | — |

引擎在 7.76 层之后有一道**白名单兜底**：不管上游哪一层写过支撑键，只要不是
`support_model.tune()` 算出来的，一律从待写列表里撤回。所以「支撑没开」时
连一个 `support_*` 键都不会写进文件。

### 八组规则（全部用模型实测值）

| 参数 | 依据 | 规则 |
| --- | --- | --- |
| 支撑线距 `support_base_pattern_spacing` | 悬垂总面积 | ≥4000→1.6、≥1500→2.0、≥400→2.5、其余 3.0 mm |
| 顶面间隙 `support_top_z_distance` | 层高 | 层高×0.7，夹 0.12~0.30 |
| 底面间隙 `support_bottom_z_distance` | 层高 | 层高×1.0，夹 0.15~0.35 |
| 水平间距 `support_object_xy_distance` | 细高比/高/底面积 | 细高比≥3 或高≥120→0.8；底面积<600 mm²→0.9；其余 0.5 |
| 接触面层数 `support_interface_top_layers` / `_bottom_layers` | 悬垂面积 | 大面积 3 层 / 零星 2 层 |
| 接触面线距 `support_interface_spacing` | 悬垂面积 | 大面积 0.5（求平整）/ 零星 0.7（求好撕） |
| 支撑线宽 `support_line_width` | 线宽基准 | ×0.9（细一点更好撕） |
| 支撑形态 `support_type` / `support_style` | 细高比、高度 | 细高比≥3.2 或高≥150 → tree(auto)；≥3.5 用 tree_strong，否则 tree_slim；大面积低矮悬垂 → normal(auto)+grid |
| 支撑速度 `support_speed` / `support_interface_speed` | 机型上限 × 模式 | 本体 ×0.55~0.85；接触面 = 本体 ×0.45~0.70（质量档最慢） |
| 质量向（quality/fine/ultrafine） | 模式 | `support_critical_regions_only=1` + 支撑熨烫（流量 10%、线距 0.15） |
| 草稿档 | 模式 | `support_remove_small_overhang=1` |

### 实测（P2S + PETG，32×45×54、悬垂 644 mm²、细高比 6.36）

```
strength  → 8 项：线宽 0.38｜本体速度 197｜顶隙 0.14｜水平距 0.9｜tree_strong｜
           界面线距 0.7｜界面速度 142｜enable_support 1
balanced  → 0 项（该模型不需要支撑，一个键都不写）
quality   → 11 项（含判定角 25°、底隙 0.15、critical_regions_only 1）
draft     → 1 项（只有判定角 35°）
```

不带模型几何（只看配置文件）时只剩 `enable_support` / `support_threshold_angle` —— 
这是刻意的：没有几何就别猜密度。

### 想改支撑策略

改 `rules/BambuRules.json` 管不到支撑定量了（那是代码里的模型公式）。
要调阈值就改 `core/support_model.py` 顶部的 `MODE_SPEED` / `MODE_IFACE` 与
`spacing_for()`，或者把 `support_policy` 里的判定角阈值调掉。
